# Проверка стабильности выбора модели и reasoning

Дата: 2026-11-15. Исправления: 1.3.12.

Исходные материалы: `docs/ignore/audit-1.md` и `docs/ignore/audit-2.md`. Их выводы сопоставлены с текущим кодом и воспроизводимыми сценариями. До изменений все 221 тест проходили: прежние проверки не покрывали ряд асинхронных переходов интерфейса.

## Что принято

| Вывод аудитов | Проверка и решение |
|---|---|
| Один клик открытия может потеряться до готовности обработчика | Подтверждён пробел в алгоритме. Кнопка заново находится при каждой проверке; клик повторяется с интервалом не менее 400 мс, только если `aria-expanded` не равен `true`. Уже открывающийся список не переключается обратно. Аналогично восстанавливается потерянный клик вложенного меню. |
| Escape отправляется до подтверждения reasoning | Подтверждён порядок действий. После клика ожидается выбранный уровень в живом меню либо его бейдж после естественного закрытия. Только затем разрешено закрытие через Escape. Тест воспроизводит обработчик, отменяющий отложенный commit при Escape. Это модель возможного сбоя, а не доказательство устройства Angular в Gemini. |
| Подтверждение reasoning получено у старой модели | Подтверждено. При смене модели прежнее подтверждение отбрасывается, уровень проверяется по меню новой модели. Подтверждение также связано с идентификатором модели. Тесты моделируют старый бейдж High или отсутствие бейджа Low, сохраняющиеся дольше окна восстановления при фактически выбранном Medium. |
| Ошибка внутри цикла пропускает следующую попытку | Подтверждено. Обработка ошибки перенесена внутрь цикла применения; временный сбой допускает вторую полную попытку с новым поиском элементов. Недоступные модели и достоверно непригодные пункты не нажимаются повторно. |
| Подпись пункта может склеиться с описанием | Подтверждено на варианте разметки без `.label`. Поддержана primary-подпись Material; запасное чтение исключает описания и декоративные значки. Неоднозначные одинаковые подписи по-прежнему не считаются подтверждением. |
| Закрывающийся overlay может сделать меню неоднозначным | Поддержана фильтрация полностью прозрачных и `aria-hidden` элементов, включая предков overlay. Два одновременно видимых подходящих меню по-прежнему считаются неоднозначностью. |
| Подменю без ARIA-связей может не находиться | Уточнено. `aria-controls`, `aria-owns`, вложенность и `aria-labelledby` уже поддерживались. Добавлен осторожный фоллбэк: только раскрытый триггер и единственный отдельный список с полной группой уровней. При конкурирующем постороннем radio-меню выбор запрещён. |
| Одно восстановление не покрывает два поздних сброса | Подтверждён предел старого алгоритма. Разрешены два восстановления в исходном 5-секундном окне. Окно не перезапускается, бесконечного автопереключения нет. Простая фокусировка prompt больше не отключает наблюдение. |
| Фоновая вкладка может исчерпать таймаут до готовности UI | Таймаут теперь расходуется только во время видимости страницы. Успешное применение в фоне разрешено. Проверяется ожидание кнопки, появляющейся позже прежних 30 секунд в скрытой вкладке. Таймаут закрытия меню получает тот же бюджет, что и остальные шаги применения. |

Дополнительно найдена гонка, отсутствующая в аудитах: фоновый скрипт читал настройки один раз перед ожиданием новой вкладки. Если в это время настройки менялись, поздняя доставка могла прислать старый снимок. Теперь перед каждой попыткой доставки выполняется актуальное чтение; запись, начавшаяся во время чтения, приводит к повторному чтению после её завершения.

## Что не принято

- **«Открывать меню ровно один раз при смене модели».** Gemini вправе сам закрыть его после выбора модели. Алгоритм должен обрабатывать закрытие и повторное открытие; принудительно сохранять старый overlay и его пункты нельзя.
- **Пакет синтетических pointer/mouse-событий поверх каждого клика.** Наличие кнопки не доказывает готовность обработчика, а дополнительные события не создают доверенное пользовательское действие. Применены ограниченные повторы обычного `click()` и отложенный hover-фоллбэк для подменю.
- **Фиксированная пауза перед каждым закрытием.** Вместо произвольных 150–300 мс ожидается наблюдаемый результат выбора; готовый интерфейс не получает обязательную задержку.
- **Продолжать автоматическое переключение во время печати.** Открытие меню способно увести фокус и помешать вводу. Реальные `keydown`/`input` и ручное управление моделью отменяют startup-восстановление, в том числе уже начатое. Клик в поле ввода сам по себе его не отменяет.
- **Бесконечно перезапускать стартовый цикл после ошибок.** Это мешало бы ручному выбору и создавало повторные открытия меню. Повторы ограничены внутри применения; после исчерпания попыток возвращается ошибка.
- **Обещание «100% при любых условиях».** DOM-автоматизация не может гарантировать работу при произвольной смене разметки Gemini, ограничениях аккаунта или запрете доступа расширению. Исправления устраняют воспроизведённые дефекты и сохраняют отказ при неоднозначности.

В аудитах также преувеличена определённость отдельных причин: live-трассировки Angular/Wiz не приложены; 3,5 секунды относятся к обычному применению, а startup уже использовал 30 секунд. Троттлинг фоновых таймеров реален, но не означает фиксированное число проверок DOM: MutationObserver тоже будит ожидание. Справочные источники: [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [Chrome timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88).

## Проверка и границы результата

- `npm run check`: синтаксис и все 237 автоматических тестов прошли, включая гонки сохранения/доставки, отложенные клики, потерю первых действий, устаревшие бейджи и повторные сбросы.
- `python tests/browser-regression.py`: 12 сценариев в изолированном настоящем Chrome/Edge, с обычным DOM, MutationObserver и асинхронными обработчиками. Проверяются замена кнопки, исчезающие overlay, inline/nested-уровни, подписи с описаниями и hover-фоллбэк. Chrome API подменён локальной заглушкой.
- После разрешения remote debugging проверен живой Gemini. На включённой магазинной 1.3.11 зафиксировано несовпадение: сохранены Argon + High, но в меню выбран Low и на кнопке отсутствует бейдж High. Распакованная копия из проекта в тот момент была отключена.
- Для проверки включена распакованная 1.3.12 и отключена магазинная копия; в распакованную перенесены Argon + High. Успешно проверены четыре восстановления после ручного Low с перезагрузкой, возврат после выбора Pro, новая активная вкладка через фоновую команду и применение в неактивной вкладке. В последнем случае content script вернул `applied: true`, пока вкладка оставалась неактивной; затем проверен ArgonHigh. Отдельно проверен `aria-checked="true"` у High в настоящем подменю.
- Наблюдение старого сбоя подтверждает симптом, но не позволяет задним числом установить, какой именно переход 1.3.11 сорвался. Внутреннее поведение Angular/Wiz и отмена commit клавишей Escape на реальном сайте не доказаны этим наблюдением.
- После ручного ввода, окончания окна startup-наблюдения или двух восстановлений расширение перестаёт исправлять последующие сбросы автоматически. Это явная граница поведения, сохраняющая управление за пользователем.

В проверенном Chrome оставлена включённой распакованная 1.3.12 с Argon + High; магазинная копия отключена. Для распакованной копии назначен прежний хоткей магазинной версии Alt+G. Уже открытые до переключения расширений пользовательские вкладки не перезагружались: их нужно обновить для подключения новой версии. Опубликованная магазинная версия не изменена. Быстрый ввод prompt и изменение popup во время загрузки покрыты автоматическими проверками, но на живом аккаунте отдельно не проверялись.
